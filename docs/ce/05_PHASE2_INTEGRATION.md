**Известные замечания менеджера по коду трека B (исправь в первую очередь, до запуска игры):**
- `Verb_TryStartCastOn_Patch` в `Source/Patches.cs`: статическое свойство `Priority` Harmony НЕ распознаёт (нужен атрибут `[HarmonyPriority(...)]`/`[HarmonyAfter]`); сейчас это мёртвый код. Реши по факту: действительно ли нужен порядок относительно CE (см. п. ниже про отчёт Harmony), и если да — задай атрибутом (и только при активном CE, например через отдельный класс патча с `Prepare()`). Комментарий над `Prepare()` врёт («возвращаем false без CE», а возвращается true) — поправь.
- В том же `Prefix` добавлены неиспользуемые параметры (`destTarg`, `surpriseAttack`, ...): имена должны точно совпадать с параметрами ванильного `Verb.TryStartCastOn` в 1.6, иначе Harmony упадёт при патче. Удали неиспользуемые, если не нужны.
- `CompatCE.cs`: `IsSuppressed` вызывает `GetComp` через хрупкую рефлексию (скорее всего тихо возвращает false); `TryInvokeCE_TryStartCastOn` и `IsCEDamageInfo` нигде не используются. Упрости: удали мёртвое, оставь работающее. Учти: в CE `DamageInfo.Instigator` обычно и так пешка-стрелок, fallback на `launcher` — запасной.
- Главное, чего трек B НЕ сделал: реальный отчёт Harmony под CE. Запусти игру с CE (`-dutypatchreport` из DutyOptim, либо временно залогируй `Harmony.GetPatchInfo` для наших целей: `Pawn.ThreatDisabled`, `Verb.TryStartCastOn`, `Thing.TakeDamage`, `Pawn.Kill`) и покажи, какие чужие префиксы/постфиксы (в т.ч. CE) стоят на тех же методах и в каком порядке. Результат в REPORT_FINAL.
