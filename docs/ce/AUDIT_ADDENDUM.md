# Поправки менеджера к AUDIT.md (приоритетнее AUDIT.md; читать обязательно всем трекам)

AUDIT.md местами догадочный. Проверено менеджером:

1. **Броня НЕЛЬЗЯ оставлять как есть (0.45/0.15 и т.п.).** В CE `ArmorRating_Sharp` — миллиметры RHA, `ArmorRating_Blunt` — МПа; ваниль-значения 0.45 в CE означают «почти ноль». Наши вещи делаются без материала (`ApparelMakeableBase`, цвет в текстуре), поэтому `StuffEffectMultiplierArmor` не работает — CE-значения задаются прямо в `statBases`. Трек A обязан: открыть CE-патч (`Patches/Core/ThingDefs_Misc/Apparel_Hats.xml`, `Apparel_Armor*.xml` и т.п. в папке CE) и взять реальные числа ближайших ванильных аналогов (SimpleHelmet, FlakVest, Duster/Jacket, Parka и т.д.), затем выставить нашим вещам **долю** от них («лёгкая броня, примерно как сейчас» = по отношению к ванильным аналогам та же доля, что у нас сейчас: наш жилет 0.45 vs ваниль flak 0.5+ → около 70–90% аналога; шлем аналогично; куртка, берет, штаны — минимум). Точное обоснование каждого числа — в REPORT_A. Заодно добавить `ArmorRating_Heat` в единицах CE (и `PartialArmorExt`, если так принято у аналогов).
2. **CE патчит Harmony-методы, которые патчим мы.** `CombatExtended.dll` содержит ссылки на `ThreatDisabled`/`TryStartCastOn` — вывод аудита «CE не патчит наши цели» НЕ подтверждён. Трек B обязан составить реальный отчёт Harmony (`harmony.GetPatchInfo` для каждого нашего метода при запущенном CE — через уже существующий инструмент DutyOptim `-dutypatchreport`, либо отдельный флаг в `SelfTest`; запуск игры делает менеджер — запроси в `HANDOFF_B.md`) и/или декомпиляцией `CombatExtended.dll` найти все такие места. Проверить префиксы CE, которые могут возвращать false раньше нашего (`Priority`/`Before` при необходимости).
3. **Карман медика** (`ParamedicUtility.SyncPocket`): это ванильный `inventoryStock` (желаемое количество медикаментов), предметы лежат в РЕАЛЬНОМ инвентаре. С CE они учитываются в Bulk/Weight. Решение: не «виртуализировать», но (а) пояс/разгрузка дают CE `CarryBulk` (трек A) достаточно под 6 бинтов/лекарств, (б) трек B проверяет, что при перегрузе по Bulk у медика нет поломки (зацикливание заданий по подбору/скидыванию медикаментов).
4. **Открытые вопросы AUDIT №1, 5, 7, 8 — решены:** `incompatibleWith` убрать; Bulk минимальные, но не ноль; карман реальный; CE-патчи формы делаем сейчас в треке A.
5. Числа Bulk из раздела 8 AUDIT.md — допустимая отправная точка, но каждое сверять с реальным значением CE для аналога (Bulk шлема/жилета/куртки в CE: SimpleHelmet 3/1, смотри остальные в файлах CE).
6. Кроме проверки в бою (трек C/Фаза 2) нужны статические проверки: все `xpath` из CE-патча находят узел (`tools\ce_xpath_check.py`).
