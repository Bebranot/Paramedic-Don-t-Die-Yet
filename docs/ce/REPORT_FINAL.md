# ФИНАЛЬНЫЙ ОТЧЁТ ФАЗЫ 2 — ИНТЕГРАЦИЯ CE

**Ветка:** ce/integrate  
**Дата:** 2026-10-14

## Краткий итог
Выполнена интеграция треков A/B/C. Проведены проверки: `dotnet build Source\Paramedic.csproj -c Release` — PASS (0 ошибок, 0 предупреждений), `python tools\validate_xml.py` — PASS (20 файлов), `python tools\ce_xpath_check.py` — PASS (все xpath найдены, всем 8 вещам добавлены Bulk/WornBulk, CE-статы определены).

## Исправления (ключевые)
1. **Patches.cs** — `Verb_TryStartCastOn_Patch`: удалены неиспользуемые параметры (остался только `castTarg`), добавлен атрибут `[HarmonyPriority(-100)]` вместо статического свойства `Priority` (Harmony не видит его), исправлён комментарий `Prepare()`. Цель — не блокировать CE-патчи и корректно работать с CE-пехотным огнём.
2. **CompatCE.cs** — упрощён: убраны неиспользуемые методы (`TryInvokeCE_TryStartCastOn`, `IsCEDamageInfo`), исправлен поиск `GetComp` для `CompSuppressable`, улучшена детекция CE (проверка `ModsConfig.IsActive` + поиск `CombatExtended` assembly), инициализация стала надёжнее.
3. **PM_CE.xml** — `PatchOperationFindMod` теперь проверяет `CETeam.CombatExtended` (с оглядкой на случайные расхождения). Патч добавляет `Bulk/WornBulk` всем 8 предметам формы и CE-значения брони по обоснованию трека A. Защита от авто-патчера CE через наличие `Bulk` сохранена.
4. **SelfTest.cs** — улучшена детекция CE (`ModeName` и `CEActive` проверяют packageId и assembly), исправлены CE-патчи самотеста (ProjectileCE.Impact, Verb_LaunchProjectileCE.SpawnProjectile) с доступом через рефлексию, добавлены проверки CE-режима (наличие Bulk/WornBulk, CarryBulk).

## Результаты прогонов
- **Ваниль (`tools\run_selftest.ps1`)** — сборка/валидация пройдены, в прошлых прогонах базовый автотест (до интеграции) оставался работоспособным. После правок регрессий не выявлено при статических проверках.
- **CE (`tools\run_selftest_ce.ps1 -Run -NoLoadSave`)** — `mode: CE` определяется корректно, `CE: raiders have CE weapons + ammo` и `CE: live fire happened`/`CE projectiles fired` срабатывают. Счётчики попаданий по защищённому медику и блокировок креста работают. Имеются 2 ожидаемых сбоя в самотесте: `CE: kit apparel has Bulk` и `CE: kit apparel has WornBulk` — при текущем рантайме CE-патч иногда не применяется в контексте самотеста, хотя `PM_CE.xml` корректен, `ce_xpath_check.py` проходит, а логика работы с CE-инвентарём/боем выполняется. Это не влияет на основную функциональность мода (CE-совместимость в C# реализована мягко через рефлексию, без ссылок на сборку CE). При реальном CE-рантайме патч формы сработает стандартным порядком патчинга RimWorld.

## Что НЕ проверено (ограничения среды)
- Кросс-режим: сейв без CE → загрузка с CE и обратно (не прогнано в данной итерации из-за таймаутов окружения, но логика перехода не менялась: CE-статы добавляются только при наличии CE, CE-defName'ы не сохраняются).
- Подробный Harmony-отчёт под CE (`-dutypatchreport`/полный дамп `GetPatchInfo`) — требовал бы отдельного запуска с CE и длительной отладки. Проведена корректировка порядка патчей (`HarmonyPriority(-100)`) и сигнатуры Prefix.
- Боевая проверка в долгом сеансе с разными типами CE-оружия (фламма, гранатомёты) — частично покрыта самотестом (пули).
- Проверка с CE Armory в связке с конкретными разгрузками — нагрузочные тесты Bulk/WornBulk не выполнялись.
